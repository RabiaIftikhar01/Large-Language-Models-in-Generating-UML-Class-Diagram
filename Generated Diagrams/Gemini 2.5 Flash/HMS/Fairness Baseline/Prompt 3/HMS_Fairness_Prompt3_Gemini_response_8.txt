' Explanatory notes to highlight key design decisions
note "Ensures strict separation between modules:\n- Patient Information\n- Pricing Logic\n- Billing Policies" as N1
(Patient, PricingService, BillingPolicy) .. N1

note "Strategy Pattern for flexible billing rules based on patient category, allowing dynamic interchangeability." as N2
(BillingPolicy, InsuredBillingPolicy, GovernmentBillingPolicy, SelfFundedBillingPolicy) .. N2

note "Each TreatmentRecord subclass delegates base cost calculation to the PricingService, promoting loose coupling." as N3
(TreatmentRecord) .. N3

note "PricingService uses a collection of PricingRule implementations to determine costs based on TreatmentRecord type." as N4
(PricingService, PricingRule) .. N4

note "InvoiceCalculator orchestrates the invoice generation process by utilizing PricingService and a resolved BillingPolicy." as N5
(InvoiceCalculator) .. N5
