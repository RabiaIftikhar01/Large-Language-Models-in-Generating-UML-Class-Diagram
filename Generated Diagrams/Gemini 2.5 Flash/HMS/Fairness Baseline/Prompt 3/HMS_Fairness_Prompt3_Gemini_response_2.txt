' --- Interfaces / Abstract Classes for Strategy Pattern ---
interface IBillingPolicy {
    + calculateFinalAmount(invoice: DischargeInvoice): decimal
}
note right of IBillingPolicy : Strategy Pattern for flexible billing logic.\nDynamically interchangeable at runtime.

interface IPricingPolicy {
    + determineUnitPrice(item: ServiceItem, quantity: int): decimal
}
note right of IPricingPolicy : Strategy Pattern for distinct pricing rules\nfor different service types.

    # serviceId: string
    # name: string
    # baseCost: decimal
    + getServiceId(): string

}
note left of ServiceItem : Base class for all billable items\n(procedures, medications, etc.).

class DischargeInvoice {

' --- Orchestration / Billing Engine ---
class BillingEngine {
    + generateInvoice(patient: Patient, servicesWithQuantities: Map<ServiceItem, int>): DischargeInvoice
    - selectBillingPolicy(category: PatientCategory): IBillingPolicy
    - getPricingPolicy(serviceItem: ServiceItem): IPricingPolicy
}
note top of BillingEngine : Orchestrates the invoice generation process,\nselecting and applying appropriate policies.

' --- Relationships ---

' Patient and Invoice: A patient can have multiple discharge invoices over time.
Patient "1" -- "0..*" DischargeInvoice : generates

' Invoice and Line Items: An invoice is composed of one or more line items.
DischargeInvoice "1" *-- "1..*" InvoiceLineItem : contains

' Line Item and Service Item: Each line item references a specific service that was provided.
InvoiceLineItem "1" -- "1" ServiceItem : references

' Service Item and Pricing Policy: Each service item uses a specific pricing rule.
ServiceItem "1" -- "1" IPricingPolicy : uses

' Billing Policy Implementations: Concrete policies realize the IBillingPolicy interface.
IBillingPolicy <|.. InsuredBillingPolicy
IBillingPolicy <|.. GovernmentBillingPolicy
IBillingPolicy <|.. SelfFundedBillingPolicy

' Service Item Specializations: Concrete service types inherit from ServiceItem.
ServiceItem <|-- MedicalProcedure
ServiceItem <|-- Medication
ServiceItem <|-- DiagnosticService
ServiceItem <|-- AccommodationCharge

' Pricing Policy Implementations: Concrete pricing policies realize the IPricingPolicy interface.
IPricingPolicy <|.. StandardPricingPolicy
' IPricingPolicy <|.. VolumeDiscountPricingPolicy

' Billing Policy Configuration: Specific billing policies use various configuration parameters.
InsuredBillingPolicy "1" -- "0..*" CoverageParameter : uses
InsuredBillingPolicy "1" -- "0..*" ReimbursementThreshold : uses
InsuredBillingPolicy "1" -- "0..*" CoPayArrangement : uses
GovernmentBillingPolicy "1" -- "0..*" SubsidyValue : uses

' Billing Engine Orchestration: The engine depends on various components to perform its task.
BillingEngine ..> Patient : generatesFor
BillingEngine ..> ServiceItem : processes
BillingEngine ..> IBillingPolicy : selectsAndApplies
BillingEngine ..> IPricingPolicy : uses
BillingEngine ..> DischargeInvoice : creates
BillingEngine ..> InvoiceLineItem : creates
BillingEngine ..> PatientCategory : uses
